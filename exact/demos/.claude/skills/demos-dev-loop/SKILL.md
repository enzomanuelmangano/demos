# Demos dev loop

```sh
cd exact/demos
export PATH=~/.bun-1.4.2/bin:~/.cargo/bin:$PATH
export CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
export EXACT_SIM=4287A1AF-1C48-462C-9E3D-3FAABC3F0119   # iPhone Air, iOS 27.1: this app's sim
bun exact.mjs contract build app.contract --json --errors-only   # [] = no errors (~1 s)
bun exact.mjs test web 'demos/**/*.test.contract' app.test.contract
bun exact.mjs ios --run --sim $EXACT_SIM                         # native build + launch
```

## Hot reload first

- Keep one development build running on `$EXACT_SIM`. An edit to any `.contract`, to
  `app.ts` or what it imports reaches it in about a second: never rebuild for those.
- Rebuild natively only for Rust (`gpu/`), Swift, `app.json`, `assets/` (icons, images),
  fonts or grants. Batch them and build once (warm: 1–2 min; first: many minutes).
- One build at a time: `pgrep -f "exact.mjs ios"` empty first; `df -h ~` above 8 GB.
- Fonts: SF Pro Rounded is the generic `ui-rounded` on Apple: no bundled file needed.

## Machine rules

- Simulators: this app uses only `$EXACT_SIM`. Never touch "Exact Try (Air)" (D3273441…),
  "RN Ref (Air)" (FF41FAED…) nor the patterns-exact agents' iPhone Air (4F281EA4…).
- `bun exact.mjs feedback` is `never`; never run `share` (it publishes a link).
- Judge motion on real time (a screen recording, argent), never under the agent's frozen clock.

## Layout of the app

- `demos.contract` is generated by `bun tools/gen-demos.ts` from the RN registry (order,
  names, icons, backdrops, inspiration links, `ported` = a folder in `demos/`). Re-run it
  after porting a demo (and rebuild only if new icons were copied).
- `home/`: the SpringBoard and the demo screen. `demos/<slug>/<slug>.contract` +
  `<slug>.test.contract`: one demo each, listed in `demos/index.contract`.
- `packages/*`: what the RN demos import from npm (pressto, …), as Contract packages.
- `gpu/` (when it exists): the Rust crate for every Skia/WebGPU/three surface.

## Parity (the owner's rule)

- Same object properties as the RN demo: every size, padding, radius, font, colour, timing,
  curve and spring copied from its code (name the RN constant in a comment). No "close enough".
- Keep every layout animation: Reanimated `layout=` becomes `-exact-layout-transition`,
  `entering`/`exiting` become `animation` + `-exact-exit-animation` with the same durations.
- Performance first: per-frame motion runs on the host (transitions, keyframes, springs,
  drag/scroll timelines, `transformDragFor`) or in Rust on the GPU, never in a commit per frame.

## Springs

- Reanimated 4 `withSpring()` with no config: `-exact-spring(900, 120, 4)` (GentleSpringConfig).
- `withSpring(v, { duration, dampingRatio })`: `bun tools/spring.ts <duration> <dampingRatio>`
  prints the exact stiffness/damping/mass (Reanimated's own bisection, mass 4 by default).
- `{ stiffness, damping, mass }` configs copy straight across; a missing key is Gentle's.
- Layout `springify()` with no setters is the same default spring.
- Overdamped: Reanimated runs any spring with damping ratio ζ = c / (2√(k·m)) ≥ 1 as
  critically damped. Contract's `-exact-spring` solves the real overdamped curve, so when ζ > 1
  write damping 2√(k·m), not RN's number. `packages/reanimated` already does this.
- `perspective` in Exact acts on a box's children (CSS), not on the box: put it on the parent of
  the rotating node.
- Contract presses ease over 120 ms (host-fixed); pressto uses 250 ms. A known host limit.

## GPU surfaces (gpu/, packages/reanimated, packages/gesture-handler)

- A `canvas` is a replaced element: `inset=0` leaves it 300×150. Give it `width`/`height`.
- Gestures and motion live in the surface: `wants_input() -> true`, recognizers from
  `gesture-handler`, animations from `reanimated`, `render()` returns true only while
  something moves or a finger is down. No commit per frame.
- `cargo test -p demos-gpu` renders offscreen (`exact_gpu::fixture`; `EXACT_GPU_OUT=/tmp/x`
  writes PPMs): check positions there before a device build.
- `Surface::agent()` answers the drive's state request: report the surface's state there.
- Never let a surface publish state that changes route props (`closedby`, presentation)
  during a gesture: the commit held the canvas's first frames ~1 s. Per-demo policy is
  static (`ownsDrags` in app.contract).
- Skia drawing goes through `packages/skia` (lyon tessellation + one MSAA pipeline): vello
  was tried and fails on the iOS Simulator (no indirect dispatch), so don't reach for it.

## Parity with RN (tools/compare.sh)

- The RN dev build runs on the same simulator (`com.reactiive.app`, Metro on 8082:
  `exp+thank-you://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8082`).
  `WAIT=5 ./tools/compare.sh <slug>…` → `/tmp/compare/sheet.png`, RN left, Exact right. A
  capture of the home or a half-open card is timing: rerun with a larger WAIT.
- GPU surfaces: one `write_buffer` per resource per frame (each stages a buffer); morphs in
  the vertex shader; the web host gives a surface no touches (iOS is the target).
- If argent's touches fail ("CoreDevice transport is dead"), `stop-simulator-server` for
  the device and retry.
